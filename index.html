02 Overview

An end-to-end IGA build implementing identity lifecycle management, access governance, certification, automated provisioning, privileged access, and SSO across midPoint and Microsoft Entra ID. Built and governed 3,000+ synthetic identities, ran access reviews with automated remediation, configured SCIM provisioning and JML workflows, tested Conditional Access and PIM, and automated bulk provisioning through Microsoft Graph and PowerShell.

Two platforms run side by side deliberately: governance concepts were built and validated in midPoint, an open-source IGA platform, independent of any single vendor, then mapped onto Entra specifically to see how the same model holds up in a real enterprise directory. Administration grants and revokes access; governance decides who should have it, why, and can prove that decision still holds up when reviewed. What follows traces both sides of that work together.

04 Data foundation

Generated a realistic synthetic dataset of 3,000+ employees for a fictional Nordic healthcare organization spanning Sweden, Denmark, and Norway.

Built a CSV connector resource in midPoint, configuring schema discovery, delimiters, and unique identifiers, then created attribute mappings translating raw CSV fields (name, title, department, locality, and more) into governed identity attributes.

Problem solved

Diagnosed a real architectural issue: accounts were being read correctly from the CSV source, but not converted into actual governed User identities. In midPoint, an Account is just raw data read from a resource, while a User (the "focus" object) is the actual governed identity that roles and policies attach to. Turning one into the other depends on a Synchronization reaction, a rule that tells midPoint what to do when it finds an account with no matching User yet. That reaction was missing, so accounts were being discovered but never linked to a User. Once configured, all 3,000 identities were imported and governed end-to-end.

05 Governance modeling & access certification

Designed custom governance roles, including Finance Analyst, IT Support, and Marketing Contributor, alongside midPoint's built-in roles, and assigned them to test identities to create a realistic access landscape to govern.

Ran a live access certification campaign in midPoint, reviewing and revoking access for specific, real reasons:

  • Access creep: identities holding access they'd accumulated over time but no longer needed.
  • Segregation-of-duties conflicts: identities holding two roles that shouldn't be combined.
  • Role/job mismatches: access that no longer matched the identity's actual job function.

Confirmed that automated remediation correctly revoked access after each case was decided, rather than just flagging it. Session notes, a command reference, and a running troubleshooting log were kept throughout the build, the same discipline this kind of audit trail depends on.

06 Scaling governance into Entra

Once the free tenant's limits became a blocker for deeper governance work, I activated a Microsoft Entra Suite trial (Identity Governance, PIM, and P2), then rebuilt the same governance model natively in Entra: Security groups with a weekly-recurring, auto-applying, owner-reviewed Access Review.

Platform lesson

Rebuilding the model natively surfaced a genuine platform distinction: the Administrator view in Entra Access Reviews is monitoring-only. The real approve/deny actions happen from the reviewer's own side, at myaccess.microsoft.com, not from the admin console.

07 Provisioning & lifecycle automation

SCIM-based provisioning

Configured SCIM-based automated provisioning against a live SCIM 2.0 test server, set up as a non-gallery Enterprise App using Bearer authentication.

Problems solved

Diagnosed and resolved a scope-assignment error, then a schema-validation error, before confirming a genuine successful provisioning event in Entra's own logs.

Lifecycle Workflows

Designed Entra ID Lifecycle Workflows for joiner/mover/leaver automation, including a time-triggered leaver workflow that fires three days after an employee's end date, scoped to a specific department, with automated license removal, Teams removal, and account deletion tasks chained together.

08 Access control depth

Least-privilege app registration

Registered a dedicated app to test Microsoft's attribute-level permission gating on the employeeLeaveDateTime attribute, confirming it requires its own narrow Graph permission with no broader substitute, and validated the end-to-end client-credentials flow via PowerShell, including token inspection and live attribute updates.

Single sign-on

Configured SSO for both major protocols: SAML via a gallery app running the full sign-in/assertion flow, and OIDC via a custom app registration, including resolving a reserved-claim-name conflict along the way.

Conditional Access & PIM

Built and tested Conditional Access policies in Report-only mode, covering MFA enforcement outside a trusted location (verified over VPN) and blocking legacy authentication. Also tested a full Privileged Identity Management lifecycle, eligible role, MFA-gated activation, justification, and approval, playing both the requestor and the approver side of the workflow.

09 Directory administration & external collaboration

Alongside the governance and provisioning work above, built out the administrative and external-collaboration surface of the tenant, the everyday configuration that governance depends on but doesn't replace.

External collaboration & guest lifecycle

Configured external collaboration settings and onboarded guest users through both the single-invite flow and a bulk CSV invite, then reproduced the same invite flow programmatically through Microsoft Graph PowerShell.

Federated identity provider

Configured Google as a federated identity provider end-to-end: registered and configured an OAuth client in Google Cloud Console, wired it into Entra External Identities, and confirmed the full B2B redemption flow, an invited guest is redirected straight to Google's own sign-in and consent screen with no separate email-verification fallback. Diagnosed and resolved an initial invalid_client error caused by an OAuth client propagation delay on Google's side.

Tenant configuration & licensing

Managed tenant-level directory properties, and configured group-based license assignment by creating a Microsoft 365 group and assigning a license to the group rather than to individual users, the standard pattern for license governance at scale.

Security baseline

Configured smart lockout thresholds to balance brute-force protection against legitimate user lockout risk, and used Identity Secure Score to benchmark the tenant's overall security posture (94.7%), triaging the one remaining recommendation, a second Global Admin, as a deliberate, accepted risk in a single-admin lab tenant rather than an oversight.

10 Capstone: bulk provisioning at scale

The exercise

Designed and executed a bulk-provisioning exercise moving ~3,000 midPoint-sourced identities into Entra ID via Microsoft Graph and PowerShell, evaluating and deciding against midPoint's native Entra connector in favor of a Bulk Create approach.

  • Fixed an authentication-architecture bug: the integration kept forcing an interactive browser/WAM broker sign-in flow, which breaks down at real scale. Resolved by switching to app-only, client-credentials authentication.
  • Proactively caught a data-quality issue affecting roughly 8% of records, before it could propagate into the target tenant.
  • Correctly diagnosed a platform quota limit using tenant-level evidence, rather than assuming the failure was a bug in the provisioning logic itself.

This project sharpened how I think about identity work: IAM and IGA matter equally, because access granted correctly once doesn't stay correct on its own. Governance is what keeps it that way.
