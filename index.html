Self-Hosted Identity Governance & Administration Lab

A dual-platform IGA environment built from the ground up to govern and administer thousands of identities — combining an open-source IGA engine with Microsoft Entra ID.

midPoint Microsoft Entra ID Oracle Cloud Docker PostgreSQL

01 Overview

I built this lab on my own initiative to go beyond the identity work I do day to day, and get hands-on with the governance side of IAM: certification campaigns, access reviews, and provisioning at scale, not just administration.

The environment runs two identity platforms side by side — midPoint, an open-source IGA platform, and a Microsoft Entra ID tenant — so I could compare how governance and provisioning are handled on each, and integrate them together.

03 Scale & provisioning

To move past small-scale testing, I generated a synthetic dataset of 3,000+ employees for a fictional Nordic healthcare organization and governed the full identity set end-to-end in midPoint.

For the Entra ID side, I evaluated midPoint's native Entra connector and decided against it, provisioning the 3,000+ identities into Entra ID via Bulk Create instead.

Problem solved

While integrating with Microsoft Graph PowerShell, I hit a reproducible authentication bug — the module kept forcing an interactive browser / WAM broker sign-in flow, which breaks down at any real scale. I diagnosed the cause and resolved it by switching to app-only, client-credentials authentication, which made the bulk provisioning work reliably and unattended.

04 Governance & access certification

Using a Microsoft Entra Suite trial (Identity Governance, PIM, and P2 features), I ran a live access certification campaign covering 13 cases — reviewing and attesting who had access to what, and why, rather than just provisioning access and leaving it unmanaged.

05 Breadth covered

Beyond the core build, the lab was also used to work hands-on with:

  • Conditional Access policy design and testing
  • Privileged Identity Management (PIM) for just-in-time privileged access
  • SSO across both SAML and OIDC
  • SCIM-based provisioning
  • Entra Lifecycle Workflows for joiner/mover/leaver automation

All of this was built and run independently, outside any job or coursework requirement — as a way to develop real IGA depth, not just IAM administration.
